# Эталонный набор

Эталонный набор для теста точности распознавания: критерий приёмки любого изменения ML-кода (см. `AGENTS.md`). Тест: `feature/session/src/jvmTest/.../AccuracyTest.kt`. Пока набора нет, тест пропускается.

## Где хранится

Набор содержит биометрию реальных людей, а основной репозиторий публичный. Поэтому набор лежит в **отдельном приватном репозитории** `koye64x/photo-finder-testdata` (файлы в Git LFS). Доступ — только у приглашённых участников и у CI.

Локально набор клонируется в папку `testdata/` внутри проекта. В основном репозитории эта папка целиком в `.gitignore`, поэтому фото нельзя случайно закоммитить в публичный репозиторий.

```bash
git lfs install                                                         # один раз на машине
git clone https://github.com/koye64x/photo-finder-testdata.git testdata # из корня проекта
git -C testdata pull                                                    # обновить набор
```

В CI набор подтягивается шагом `actions/checkout` с deploy-ключом из секрета `TESTDATA_DEPLOY_KEY`. Если секрета нет (например, в PR из форка), тест точности пропускается.

На планшет набор попадает копированием `testdata/event-photos/` в папку мероприятия на microSD/USB (картридер или `adb push`).

## Структура

```
testdata/
├── event-photos/          # фото мероприятия (вход индексации): JPEG/PNG, любые имена
│   └── .gitkeep           # заглушка, чтобы git хранил пустую папку; удалить не обязательно
├── guest-camera/
│   ├── .gitkeep           # то же
│   └── <person>/          # кадры человека с фронтальной камеры (вход сессии гостя): 3–5 фото
├── labels.csv             # кто на каком фото; пока только заголовок
├── SOURCES.md             # откуда каждое фото и чьё согласие его покрывает
├── README.md              # пометка «приватно» и ссылка на этот документ
└── .gitattributes         # *.jpg, *.jpeg, *.png, *.heic, *.mp4 — в Git LFS; остальное — обычным текстом
```

После калибровки порогов добавляется `accuracy.properties` (см. «Запуск и отчёт»), до этого его нет.

Тест точности читает только JPEG и PNG (`.jpg`, `.jpeg`, `.png`, регистр не важен). HEIC на JVM не декодируется: такие снимки перед добавлением нужно сконвертировать в JPEG. Правила LFS для HEIC и MP4 заведены заранее: на случай исходников с iPhone и видео для будущих тестов сессии.

`labels.csv` — заголовок и по строке на каждое появление человека на фото. Имя человека совпадает с именем папки в `guest-camera/`. Фото без известных людей в разметке не перечисляются.

```csv
photo,person
IMG_0012.jpg,p01
IMG_0012.jpg,p02
IMG_0040.jpg,p01
```

Вместо имён — коды (`p01`, `p02`…); соответствие кодов людям хранится у того, кто собирает набор, не в репозитории.

## Состав

Минимум для первой калибровки:
- 20 человек, около 300 фото мероприятия, 3–5 селфи на человека;
- групповые фото (5–20 лиц), портреты, фото издалека;
- профиль и полупрофиль, очки, головные уборы, плохой и смешанный свет, движение;
- люди, которых нет среди запросов (проверка ложных совпадений);
- селфи снимать отдельно от фото мероприятия, желательно в другой день или при другом свете.

## Запуск и отчёт

```bash
./gradlew :feature:session:jvmTest --tests '*AccuracyTest*'
```

Для каждой модели эмбеддингов из `models/` тест пишет таблицу по сетке порогов в `feature/session/build/reports/accuracy/<model>.md`: версию набора (коммит `testdata/`), recall и precision для группы «точно» и для «точно + возможно», время индексации на фото. В CI отчёт выкладывается артефактом `accuracy`. По этим таблицам выбирается модель и пороги и создаётся `testdata/accuracy.properties`:

```properties
model=sface-2021dec
sure=0.45
maybe=0.35
minRecallAll=0.90
minPrecisionSure=0.98
```

После этого тест падает, если recall («точно + возможно») или precision («точно») опускаются ниже зафиксированных значений. Сравнения «до и после» в PR делаются на одной версии набора.

## Правила

- Только лица с явным письменным разрешением (шаблон — [testdata-consent-template.md](testdata-consent-template.md)) или синтетические. Фото реальных людей из интернета не добавлять.
- Подписанные согласия хранятся у того, кто собирает набор, не в репозитории. В `SOURCES.md` для каждого фото указать автора и коды людей, чьи согласия его покрывают.
- Если человек отзывает согласие, его фото и селфи удаляются из набора, а репозиторий набора пересоздаётся без них (история с удалёнными фото не сохраняется; объекты Git LFS на GitHub удаляются только вместе с репозиторием). Код проекта от этого не зависит.
- Пороги в `accuracy.properties` меняются только отдельным PR (в репозиторий набора) с обоснованием и значениями до и после.
